## Context

Some catalog operations are slow or bursty: enriching products, processing images, and ingesting large supplier feeds. Running this work inline in the [[service|product-api]] request path would make API latency unpredictable.

## Decision

The Product API handles validation, persistence and the outbox write synchronously, then returns. Enrichment, media processing and bulk imports must run in the [[service|product-worker]], never in the Product API request path.

## Consequences

- The Product API stays fast under load.
- Some product attributes are populated after creation, so consumers must not assume every derived field is present immediately.
